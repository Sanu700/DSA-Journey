# 621. Task Scheduler

## Pattern

Greedy + Max Heap

## Intuition

The same task must have at least `n` intervals between two executions.

The task with the highest frequency is the most dangerous because it is most likely to create idle time.

So always execute the task with the highest remaining frequency first.

A cooldown cycle has:

   n + 1 slots

Why?

If we execute:

   A

then A cannot appear for the next `n` intervals:

   A → _ → _ → ... → _

So one complete cycle contains `n + 1` positions.

## Approach

1. Count the frequency of every task.

2. Put all non-zero frequencies into a Max Heap.

3. While tasks remain:

   - Start a cycle of at most `n + 1` slots.
   - Repeatedly take the most frequent task from the heap.
   - Execute it and decrease its frequency.
   - If it still has remaining occurrences, temporarily store it.

4. After the cycle ends, put the remaining frequencies back into the heap.

5. Count every executed task and every required idle interval.

6. Return the total time.

## Time Complexity

O(N log 26)

- `N` = number of tasks.
- There are at most 26 different task types.
- Since 26 is constant, this is effectively O(N).

## Space Complexity

O(26)

- Frequency array, heap, and temporary storage contain at most 26 task types.
- Effectively O(1) extra space.

## Interview Note

- Think **"Most frequent task first."**
- Use a Max Heap to always select the task with the highest remaining frequency.
- One cooldown cycle has `n + 1` slots.
- Tasks that are executed but still have remaining occurrences go into temporary storage and return to the heap after the cycle.
- Don't add unnecessary idle time after all tasks are finished.

## Mental Model

For:

   A A A B B B

and:

   n = 2

Each cycle has:

   n + 1 = 3 slots

Schedule:

   A B idle
   A B idle
   A B

Total:

   8

The frequent tasks A and B are spread across different cycles.

## Key Idea

**Max Heap → take most frequent task → execute → decrease frequency → repeat after cooldown.**

The most important observation:

**Cooldown `n` → cycle size `n + 1`.**
