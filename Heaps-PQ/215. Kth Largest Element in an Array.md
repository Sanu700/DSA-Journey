# 215. Kth Largest Element in an Array

## Pattern

Min Heap of Size K

## Intuition

We only need the `k` largest elements, not the entire sorted array.

Maintain a Min Heap containing the `k` largest elements seen so far.

The smallest element among these `k` elements is the kth largest overall.

## Approach

1. Create a Min Heap.

2. Traverse every element in the array.

3. Add the current element to the heap.

4. If the heap size becomes greater than `k`, remove the smallest element.

5. After processing all elements, the heap contains the `k` largest elements.

6. The top of the Min Heap is the kth largest element.

## Time Complexity

O(n log k)

- Each element is inserted into a heap of size at most `k`.
- If the heap exceeds `k`, one element is removed.

## Space Complexity

O(k)

- The heap stores only `k` elements.

## Interview Note

- Think **"Kth largest → Min Heap of size K."**
- Keep only the `k` largest elements.
- The smallest among those `k` elements is the answer.
- Don't build a heap of all `n` elements unless simplicity is more important than optimization.

## Mental Model

For `k = 3`:

   Stream → 5, 2, 8, 10, 4

Keep the 3 largest:

   [5, 8, 10]

Min Heap:

       5
      / \
     8   10

Top = `5`

Therefore `5` is the 3rd largest.

When a larger element arrives:

   12

Push:

   [5, 8, 10, 12]

Heap size > 3 → remove smallest:

   [8, 10, 12]

Now top = `8`, which is the 3rd largest.

## Key Idea

**Kth largest → Min Heap + size K**

For every element:

   push
     ↓
   size > k?
     ↓ yes
   pop smallest

At the end:

   heap.top() = kth largest
