# 973. K Closest Points to Origin

## Pattern

Max Heap of Size K

## Intuition

We need the `k` closest points, so we only need to keep the best `k` points seen so far.

Use a Max Heap where the farthest point among those `k` points stays at the top.

Whenever we get a new point:

- Add it to the heap.
- If we now have more than `k` points, remove the farthest one.

At the end, the heap contains exactly the `k` closest points.

## Approach

1. For each point `(x, y)`, calculate its squared distance from the origin:

   `x² + y²`

2. Store the distance and point/index in a Max Heap.

3. If the heap size becomes greater than `k`, remove the top element.

   Since it is a Max Heap, the top is the farthest point.

4. After processing all points, the heap contains the `k` closest points.

5. Extract all points from the heap into the answer.

## Time Complexity

O(n log k)

- Each point is inserted into a heap of maximum size `k`.
- Each insertion/removal costs O(log k).

## Space Complexity

O(k)

- The heap stores at most `k` points.
- The output array is not counted as extra working space.

## Interview Note

- Think **"K closest → Max Heap of size K."**
- Keep only the best `k` points.
- The worst among the current `k` stays at the top so it can be removed easily.
- Don't calculate the actual Euclidean distance using `sqrt`.
- Use `x² + y²` because it preserves the distance ordering.

## Mental Model

Suppose `k = 3`.

Keep:

   [closest]
   [closest]
   [farthest] ← heap top

When a new point arrives:

   push(new point)

If size becomes 4:

   pop() → remove the farthest

So after every step:

   Heap = 3 closest points seen so far

## Key Idea

**K closest → Max Heap of size K**

For every point:

   calculate x² + y²
          ↓
        push
          ↓
   size > k?
      ↓ yes
     pop

At the end, the heap contains the `k` closest points.
