# 23. Merge k Sorted Lists

## Pattern

Min Heap + Linked List

## Intuition

We have `k` sorted linked lists.

At any point, the smallest possible node must be one of the current heads of the `k` lists.

So keep the current head of every list inside a Min Heap.

The heap always gives us the smallest node.

After taking a node, add its `next` node to the heap.

## Approach

1. Create a Min Heap that compares nodes by their values.

2. Insert the head of every non-empty list into the heap.

3. Create a dummy node to build the result list.

4. While the heap is not empty:

   - Take the smallest node.
   - Attach it to the result.
   - If that node has a next node, push the next node into the heap.

5. Return `dummy.next`.

## Time Complexity

O(N log k)

- `N` = total number of nodes across all lists.
- Every node is inserted and removed from the heap once.
- Heap contains at most `k` nodes.

## Space Complexity

O(k)

- At most one node from each list is present in the heap.
- The result list reuses the existing nodes.

## Interview Note

- Think **"Keep the smallest current node from every list."**
- Min Heap always gives the globally smallest available node.
- After removing a node, only its `next` can become the next candidate from that list.
- Dummy node makes result construction clean.

## Mental Model

Suppose:

   1 → 4 → 5
   1 → 3 → 4
   2 → 6

Initially:

   Heap = [1, 1, 2]

Take smallest:

   1

Push its next:

   Heap = [1, 2, 4]

Take:

   1

Push its next:

   Heap = [2, 3, 4]

Continue until the heap is empty.

Result:

   1 → 1 → 2 → 3 → 4 → 4 → 5 → 6

## Key Idea

**K sorted lists → put K current heads into a Min Heap.**

**Pop smallest → add to answer → push its next.**

This gives the optimal practical solution:

**O(N log k) time and O(k) extra space.**
