# 146. LRU Cache

## Pattern

HashMap + Doubly Linked List

## Intuition

We need both:

- O(1) lookup by key
- O(1) removal/insertion based on usage order

A HashMap gives O(1) lookup, while a Doubly Linked List maintains the LRU → MRU order and allows O(1) insertion/removal.

So combine them:

   HashMap:
   key → Node*

   Doubly Linked List:
   LRU ←→ ... ←→ MRU

Use two dummy nodes:

   head ↔ LRU ↔ ... ↔ MRU ↔ tail

- `head->next` = least recently used
- `tail->prev` = most recently used

## Approach

1. Store every key's node in a HashMap.

2. Maintain a Doubly Linked List ordered from:
   
   LRU → MRU

3. On `get(key)`:

   - If key doesn't exist, return `-1`.
   - Otherwise, remove the node from its current position.
   - Insert it just before `tail`.
   - Return its value.

   Accessing an item makes it most recently used.

4. On `put(key, value)`:

   - If the key already exists:
     - Update its value.
     - Move it to MRU.

   - Otherwise:
     - Create a new node.
     - Add it to MRU.
     - Add it to the HashMap.

5. If the cache exceeds capacity:

   - The LRU node is `head->next`.
   - Remove it from the linked list.
   - Erase its key from the HashMap.
   - Delete the node.

## Time Complexity

O(1)

- `get` → O(1)
- `put` → O(1)
- Insert/remove → O(1)
- HashMap lookup/erase → O(1) average

## Space Complexity

O(capacity)

- HashMap stores at most `capacity` nodes.
- Doubly Linked List stores at most `capacity` nodes.

## Interview Note

- Think **"HashMap for finding, Doubly Linked List for ordering."**
- Every HashMap entry points directly to a linked-list node.
- Never search the linked list for a key.
- `head->next` is always LRU.
- `tail->prev` is always MRU.
- Every `get` makes that node MRU.
- Existing `put` also makes that node MRU.

## Mental Model

Suppose capacity = 3:

   head ↔ 1 ↔ 2 ↔ 3 ↔ tail
          LRU       MRU

If we `get(1)`:

   head ↔ 2 ↔ 3 ↔ 1 ↔ tail
          LRU       MRU

Now if we `put(4)`:

   head ↔ 2 ↔ 3 ↔ 1 ↔ 4 ↔ tail

Capacity is exceeded, so remove `2`:

   head ↔ 3 ↔ 1 ↔ 4 ↔ tail

Therefore `2` is evicted.

## Key Idea

**HashMap tells us WHERE the node is.**

**Doubly Linked List tells us WHO is LRU/MRU.**

Together they give:

   get → O(1)
   put → O(1)
