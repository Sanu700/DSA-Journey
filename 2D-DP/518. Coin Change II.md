# 518. Coin Change II

## Pattern

1D Dynamic Programming + Unbounded Knapsack

## Approach

1. Create a `dp` array where:

   dp[j] = number of combinations that can make amount j

2. Initialize:

   dp[0] = 1

   There is exactly one way to make amount `0`: choose nothing.

3. Traverse the coins in the outer loop.

   for(int coin : coins)

   This ensures that different orders of the same coins are not counted separately.

   For example:

   1 + 2

   and

   2 + 1

   are counted as one combination.

4. For each coin, traverse the amounts from `coin` to `amount`:

   for(int j = coin; j <= amount; j++)

5. Use the transition:

   dp[j] += dp[j - coin]

   This means:

   Number of ways to make j
   =
   existing ways
   +
   ways to make j - coin and then add this coin

6. Iterate the amount forward because each coin can be used unlimited times.

7. Return `dp[amount]`.

## Time Complexity

O(n × amount)

- `n` is the number of coins.
- For every coin, we process all amounts up to `amount`.

## Space Complexity

O(amount)

- We only use a 1D DP array.

## Interview Note

- Think **"How many ways can I make this amount using the coins I've considered?"**
- This is an **unbounded knapsack** problem because every coin can be used unlimited times.
- The important loop order is:

   coin → amount

- Amount must go **forward** because coins can be reused:

   for(int j = coin; j <= amount; j++)

- The key transition is:

   dp[j] += dp[j - coin]

- `dp[0] = 1` is the important base case.
- Unlike Coin Change I:

   Coin Change I → minimum number of coins → `min()`

   Coin Change II → number of combinations → `+=`

- If intermediate DP values can exceed `INT_MAX`, cap them at `INT_MAX` to prevent integer overflow when the required final answer is still within the allowed range.
